# Skill manager requirement audit

This is a design-wide source and evidence map for [the design](skill-manager-design.zh-CN.md),
including requirements outside §11.1. It does **not** certify complete product acceptance. Test-file
links identify executable contracts; a link alone is not a fresh test result. Recorded executions,
failures, environments and active jobs remain in [implementation status](skill-manager-implementation-status.md).
The nineteen required timing scenarios have their separate [interleaving audit](skill-manager-interleaving-audit.md).

The current full gates cover CLI contracts, Server transactions and portable Node tests. Opt-in Linux,
PostgreSQL, kernel, daemon, capacity and model tests must retain their own execution evidence; skipped
opt-in tests do not count as acceptance. Synthetic Claude-format tools prove filesystem/lifecycle
behavior, not actual model discovery or learning.

## Release decision — 2026-09-27

The user authorized release before the remaining real Linux, genuine Docker Sandbox and actual
model acceptance, to be completed after release with their assistance. The pending acceptance
boundaries below remain pending; publication is not additional acceptance evidence.

Deployment bundle **0.2.42** and Server **0.2.27**, Node **0.2.29**, CLI **0.2.32** are now
published through their prepare/release Actions. Exact component commits, supply-chain checks and
current CI results are recorded at the top of [implementation status](skill-manager-implementation-status.md).
R46/R49 and each row's real-runtime boundary remain open; successful publication and faster checks
do not complete those requirements. Remaining real-environment runs await the user's agreed
post-release assistance, rather than another automatic acceptance attempt.

## Completion decision

The bounded recovery source, Helper lifecycle/stream, gateway negotiation and CLI disk index are
implemented. Actual Linux source/Helper and 100,001-entry CLI component checks passed; complete
small negotiated SSH passed. Actual 100,001-entry SSH (88590) also passed full bundle, revocation and
unchanged-source checks. New-format paced >900-second continuation (49223) also passed. Actual destination exhaustion, staging cleanup and fresh complete retry also passed (71250).
New-format 10 GiB + 1 MiB recovery also passed independently (6924), including complete object
verification, revocation and unchanged source. R17/R41 now have direct recovery acceptance at these
entry/byte/duration/failure boundaries. They do not imply Docker Sandbox support or arbitrary throughput. Combined 11193 completed first publication/reclamation but failed
successor admission. Its fixture's global HTTP lock could block heartbeats; a real HTTP reproduction
and regression tests justify removing that lock using transaction-local test capability injection.
That repair does not establish the historical 409 or original 11363 second-finalization cause.
See the latest execution record for exact resource ownership, results and remaining acceptance.

The command, storage and Native runtime implementation has substantial executable coverage, but the
design is not complete. R46 and R49 retain explicit real-environment acceptance work. R48 now has explicit interrupted
source repair and actual cross-kernel/production-daemon recovery evidence. Final full Server
quality passes (57467: 1857 passed, 102 skipped, 82.95% coverage), alongside final targeted checks
and complete Node/CLI quality gates. Other rows name their current verification layer; they do not turn separately
executed component tests into an unexecuted complete runtime scenario. The full design cannot be
marked delivered while these gaps remain.
